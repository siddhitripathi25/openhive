# OpenHive User Flow

## Objective

The goal of OpenHive is to help a beginner developer go from zero open-source experience to their first accepted Pull Request (PR).

---

# User Journey

## Step 1: Landing Page

User visits OpenHive.

The landing page explains:

* What OpenHive does
* Why open source matters
* How OpenHive helps beginners
* Success stories (future)

Primary CTA:

"Start Your Open Source Journey"

---

## Step 2: GitHub Authentication

User clicks:

"Continue with GitHub"

OpenHive retrieves:

* GitHub username
* Profile information
* Public repositories
* Contribution statistics

User account is created.

---

## Step 3: Onboarding & Skill Assessment

User answers a short questionnaire.

### Questions

What languages do you know?

* JavaScript
* Python
* Java
* C++
* Go
* Other

Experience Level:

* Beginner
* Intermediate
* Advanced

Interested Domains:

* Web Development
* Backend
* AI/ML
* DevOps
* Mobile Development
* Open Source Tools

Goal:

* First Contribution
* Improve GitHub Profile
* Learn Open Source
* Build Portfolio

---

## Step 4: Dashboard

User enters their dashboard.

Dashboard contains:

### Recommended Repositories

Repositories matched to user skills.

### Recommended Issues

Beginner-friendly issues.

### Progress Tracker

Current contribution progress.

### Learning Resources

Helpful documentation and guides.

---

## Step 5: Repository Discovery

User clicks a repository.

Repository Page shows:

* Project overview
* Tech stack
* Difficulty level
* Activity level
* Contribution guidelines
* Setup instructions

Goal:

Help the user quickly understand the repository.

---

## Step 6: Issue Selection

User chooses an issue.

Issue Page shows:

* Issue title
* Description
* Difficulty level
* Estimated effort
* Related files
* Suggested starting point

Goal:

Reduce confusion and help users start confidently.

---

## Step 7: Contribution Roadmap

OpenHive generates a step-by-step roadmap.

Example:

1. Fork repository
2. Clone repository
3. Setup project locally
4. Understand issue requirements
5. Modify code
6. Test changes
7. Commit changes
8. Push branch
9. Create Pull Request

Progress is saved automatically.

---

## Step 8: Contribution Tracking

User updates progress.

Possible statuses:

* Not Started
* In Progress
* PR Submitted
* PR Under Review
* PR Merged

Dashboard reflects current status.

---

## Step 9: First PR Achievement

When a user submits their first Pull Request:

OpenHive celebrates the milestone.

Example:

🎉 First Pull Request Submitted

User receives:

* Achievement badge
* Contribution history record
* Motivation to continue

---

## Step 10: First Accepted PR

When the PR gets merged:

🎉 First Accepted PR

User profile updates.

Contribution becomes part of their public OpenHive profile.

---

# MVP End State

A beginner developer successfully:

* Finds a repository
* Finds an issue
* Understands the contribution process
* Submits a Pull Request
* Gets their first accepted PR

This is the primary success outcome of OpenHive MVP.
